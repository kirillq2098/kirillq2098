# AGENTS.md

Правила для ChatGPT, Codex, Cursor и других AI-агентов, которые обновляют этот репозиторий.

## Цель

Поддерживать профессиональное портфолио Кирилла Акулова как проверяемый и актуальный источник информации для работодателей, заказчиков и будущего персонального сайта.

## Главный принцип

**Не выдумывать достижения.**

Любое техническое или карьерное утверждение должно быть основано хотя бы на одном из источников:

- фактический публичный репозиторий;
- документация приватного проекта, доступная владельцу;
- runtime/deployment evidence;
- подтверждённая владельцем информация.

## Не смешивать статусы

Наличие кода != production.

Наличие тестов != production.

План != реализованная функция.

Прототип != production-ready product.

Использовать термины `CONFIRMED`, `IMPLEMENTED`, `IN PROGRESS`, `PLANNED`, когда статус критичен для смысла.

## Публичная безопасность

Перед каждым изменением проверять, что в commit не попадают:

- credentials;
- API tokens;
- webhook secrets;
- production connection strings;
- внутренние CRM identifiers, если они не нужны публично;
- клиентские данные;
- персональные финансовые данные;
- домашние адреса и документы;
- внутренние документы компании.

## Стиль портфолио

- конкретика вместо маркетинговых клише;
- реальные проблемы и архитектурные решения вместо списка buzzwords;
- язык профессионального инженера, но доступный recruiter/hiring manager;
- не использовать `guru`, `ninja`, `rockstar`, `10x engineer` и подобные оценки;
- не называть владельца Senior/Architect только ради статуса;
- показывать профессиональную траекторию отдельно от текущего фактического уровня;
- если есть измеримый impact, он важнее количества технологий.

## При добавлении нового проекта

Собрать:

1. Problem
2. Context
3. Constraints
4. Role
5. Architecture
6. Implementation
7. Evidence
8. Impact
9. Stack
10. Status

После этого синхронно обновить:

- `data/profile.json`;
- `README.md`;
- `README.en.md` при существенном изменении;
- `docs/PROJECTS.md`;
- `CHANGELOG.md`.

## Будущий сайт / Notion

Не дублировать факты вручную, если их можно взять из `data/profile.json`. Структурированные данные должны оставаться переносимыми между GitHub, сайтом, Notion и резюме.
